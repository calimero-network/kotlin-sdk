`Mero` is the SDK facade — a plain class constructed from a `MeroConfig`. It owns
the OkHttp transport, the token state, and a single-flight `RefreshCoordinator`,
and exposes the API clients. Every call is a `suspend` function except the
`isAuthenticated` property.

## Constructor

```kotlin
class Mero(config: MeroConfig)

val mero = Mero(MeroConfig(baseUrl = "https://your-node.example"))
```

## Authentication

```kotlin
suspend fun authenticate(credentials: Credentials? = null): TokenData
```

Authenticate with credentials (falls back to `config.credentials`; throws
`MeroStateException` if neither is set). Sends a `user_password` token request
with client name `mero-kotlin-sdk` and permissions `["admin"]`, then persists and
returns the bundle. No `bootstrap_secret`: core stopped honouring it.

## Token state

```kotlin
val isAuthenticated: Boolean               // is a bundle present?
fun getTokenData(): TokenData?             // current bundle (debug / handoff)
fun setTokenData(data: TokenData)          // set directly; derives expiresAt from the JWT when 0
suspend fun logout(clientId: String? = null)  // clear locally + best-effort server revoke
fun clearToken()                           // drop the bundle + clear the store (local only)
```

<Aside type="note">
  There is no `close()` — a `Mero` holds no long-lived resources of its own. To
  stop a live [`events(...)`](/reference/events/) stream, cancel the coroutine
  collecting it.
</Aside>

## SSO statics

On `Mero`'s companion (also available as top-level functions in
`com.calimero.mero.auth`):

```kotlin
fun parseAuthCallback(
    url: String,
    allowUnsolicited: Boolean = false,
    pending: PendingAuthStates = PendingAuthStates.shared,
    allowCustomScheme: Boolean = false, // a non-https callback is refused without it
): AuthCallbackResult?
fun buildAuthLoginUrl(
    nodeUrl: String,
    options: AuthLoginOptions,
    pending: PendingAuthStates = PendingAuthStates.shared,
): String
```

`buildAuthLoginUrl` records a single-use `auth_state` in `pending` and adds it to
the callback URL; `parseAuthCallback` returns `null` for a callback that carries
no pending state (unless `allowUnsolicited`). See
[only callbacks this app asked for](/get-started/authentication/#only-callbacks-this-app-asked-for).

```kotlin
class PendingAuthStates(
    store: SecureStore = MemorySecureStore(),   // EncryptedPrefsSecureStore to survive process death
    clock: () -> Long = System::currentTimeMillis,
) {
    fun begin(): String                 // a fresh state, 16 random bytes hex, 10-minute lifetime
    fun take(state: String?): Boolean   // spend it: true once, if pending and unexpired
    fun clear()
    companion object { var shared: PendingAuthStates }
}
```

```kotlin
data class AuthCallbackResult(
    val accessToken: String, val refreshToken: String, val applicationId: String,
    val contextId: String, val contextIdentity: String, val nodeUrl: String,
)

data class AuthLoginOptions(
    val callbackUrl: String, val mode: String,
    val permissions: List<String>? = null,
    val packageName: String? = null, val packageVersion: String? = null, val registryUrl: String? = null,
)
```

On Android, `SsoLauncher.launch(context, nodeUrl, options, pending)` opens the login URL in
a Chrome Custom Tab, pinned to the browser. See [authentication](/get-started/authentication/#hosted-sso-deep-link).

## Configuration types

### `MeroConfig`

```kotlin
data class MeroConfig(
    val baseUrl: String,
    val credentials: Credentials? = null,
    val timeoutMs: Long = 10_000,        // connect/read/write; default 10s
    val tokenStore: TokenStore? = null,  // defaults to in-memory when null
    val refreshLockFile: File? = null,   // cross-process refresh lock; null = in-process only
    val requestProof: ProofSigner? = null, // sign each request (X-Calimero-Proof); see below
)
```

`requestProof` signs every request with a device key: its method, its path and query,
and its exact body, sent as `X-Calimero-Proof`. It is mero-js's
`MeroJsConfig.requestProof`. Build one with `createProofSigner(ProofCredential(...))`
or `createProofSigner(ProofSignerOptions(...))`. With a proof configured, the HTTP
clients do not follow redirects, and a 3xx throws `ProofRedirectRefusedException`. SSE
and the WebSocket send the session token when there is one, and the proof otherwise.
See [request proofs](/guides/signing/#request-proofs-x-calimero-proof).

data class Credentials(

### `TokenData`

```kotlin
data class TokenData(
    val accessToken: String,   // wire: access_token
    val refreshToken: String,  // wire: refresh_token
    val expiresAt: Long,       // wire: expires_at (epoch ms; derived from the JWT `exp`)
    val nodeOrigin: String? = null, // wire: node_origin — the issuing node, set by Mero on persist
)

fun nodeOriginOf(baseUrl: String): String  // "https://host/node1/" → "https://host/node1"
```

Wire/storage keys are snake_case, portable with the mero-js token bundle. Pass
`expiresAt = 0L` to `setTokenData` to have the SDK derive the real expiry from the
access token's JWT.

`Mero` tags every bundle it persists with `nodeOrigin = nodeOriginOf(baseUrl)`
(origin plus path prefix, as mero-js's `node_origin`) and reads a stored bundle
tagged for another node — or untagged, from before the field existed — as empty,
so tokens are never sent to a node that did not issue them. `getTokenData()`
returns bundles without the tag; `clearToken()` leaves another node's bundle in a
shared store alone.

## Token stores

```kotlin
interface TokenStore {          // synchronous; implementations must be thread-safe
    fun getTokens(): TokenData?
    fun setTokens(data: TokenData)
    fun clear()
}

class MemoryTokenStore : TokenStore   // ephemeral (default when config.tokenStore is null)

class EncryptedPrefsTokenStore(       // AndroidX EncryptedSharedPreferences, hardware-backed key
    context: Context,
    fileName: String = "mero_tokens", // distinct names isolate multiple nodes
) : TokenStore
```

`EncryptedPrefsTokenStore` requires an Android `Context`. The `TokenStore`
interface is **synchronous** — an async backend must be wrapped in a
synchronous in-memory cache primed at startup.
