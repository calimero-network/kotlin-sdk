mero-kotlin streams a node's real-time context events over Server-Sent Events,
exposed as a Kotlin `Flow`. The task-oriented walkthrough is the
[live events guide](/guides/events/); this page is the API surface.

## `mero.events(contextIds)`

```kotlin
fun events(contextIds: List<String>): Flow<ContextEvent>
```

Opens `GET /sse` and subscribes to the given context ids via
`POST /sse/subscription`, then emits a `ContextEvent` per node emission. The
returned `Flow` is cold — collecting it opens the connection; cancelling the
collecting coroutine closes it. It reconnects automatically 3 s after a drop (a fixed
delay, as in mero-js) and re-subscribes.

```kotlin
val job = scope.launch {
    mero.events(listOf(contextId)).collect { event ->
        println("${event.contextId} · ${event.kind}")
    }
}
// later:
job.cancel()   // closes the SSE stream
```

## Group events (core 0.11.0-rc.83)

```kotlin
fun groupEvents(groupIds: List<String>): Flow<GroupEvent>
fun nodeEvents(contextIds: List<String>, groupIds: List<String>): Flow<NodeEvent>
```

Subscribing with `groupIds` delivers group-keyed frames — membership changes and
migration progress, `result.groupId` rather than `result.contextId` — as
`GroupEvent(groupId, kind, payload)`. Roles in them may read `RelayTee`. The node
silently drops ids the token may not observe. `groupIds` is sent only when
non-empty, so a context-only subscription is byte-identical to before.

The stream authenticates with an `Authorization: Bearer` header on `/sse`, like
every other call. Core rc.83 also accepts a `?token=` query on `/ws`, `/sse` and
`/sse/*` (for browsers), but a token in a URL ends up in proxy logs.

## `ContextEvent`

```kotlin
data class ContextEvent(
    val contextId: String,
    val kind: String,          // "StateMutation" | "SyncStatus" | …
    val payload: JsonElement,  // the raw event JSON
)
```

The discriminator is the frame's `result.type`. A live `merod 0.11.0-rc.32` sends
**`StateMutation`** (the context state moved) and **`SyncStatus`**
(`syncing` / `waitingForPeers` / …). It does **not** send `ExecutionEvent`, which
earlier versions of this page named — a `when` branching on it never fired.

A presence update (`kind == "Ephemeral"`) carried by a relay for an account
names that account; read it as `event.presenceAccount` (`null` for a node's own
presence).

For a contract emission (`kind == "StateMutation"`) the encoded contract events
live under `payload`'s `data.events[].data`, each with its own `kind`.

## `mero.sse` — `SseConnection`

With `authorize` set (for example `createProofAuthorizer(ProofCredential(...))`), every
`GET /sse` and subscription POST carries the headers it returns for that request's
method, path and body, in place of the Bearer token. A proof-carrying request never
follows a redirect, and the 3xx is reported on `errors` as
`ProofRedirectRefusedException`. `SseClient` and `WsClient` (for the `GET /ws` upgrade)
take the same hook. See [request proofs](/guides/signing/#request-proofs-x-calimero-proof).

```kotlin
class SseConnection(
    baseUrl: String,
    token: suspend () -> String?,
    client: OkHttpClient = OkHttpClient(),
    json: Json = …,
    reconnectDelayMs: Long = 3_000,
    now: () -> Long = System::currentTimeMillis,
    authorize: RequestAuthorizer? = null,      // per-request headers (a request proof); wins over token
) {
    val events: SharedFlow<NodeEvent>          // hot; collect before connect()
    val contextEvents: Flow<ContextEvent>
    val groupEvents: Flow<GroupEvent>
    val appVersionChanges: Flow<AppVersionChangedEvent>
    val migrationEvents: Flow<GroupMigrationEvent>
    val membershipEvents: Flow<GroupMembershipEvent>
    val connects: SharedFlow<String>           // session id, after the re-subscribe landed
    val errors: SharedFlow<Throwable>
    val failure: StateFlow<Throwable?>         // the terminal refusal, if any
    val sessionId: String?

    fun connect()
    suspend fun subscribe(contextIds: Collection<String> = emptyList(), groupIds: Collection<String> = emptyList())
    suspend fun unsubscribe(contextIds: Collection<String> = emptyList(), groupIds: Collection<String> = emptyList())
    fun isSubscribed(contextId: String): Boolean
    fun isSubscribedToGroup(groupId: String): Boolean
    fun presenceSeed(contextId: String): List<JsonObject>
    fun onAppVersionChanged(handler: (AppVersionChangedEvent) -> Unit): () -> Unit
    fun onMigrationEvent(handler: (GroupMigrationEvent) -> Unit): () -> Unit
    fun close()
}
```

Port of mero-js `SseClient`. `subscribe` / `unsubscribe` on a live session POST
`/sse/subscription` `{"id": <session>, "method": "subscribe" | "unsubscribe",
"params": {contextIds?, groupIds?}}` with only the ids that changed, under a 10 s
timeout. On every `connect` frame the whole remembered set is re-subscribed, then
`connects` emits. Reconnection waits a fixed `reconnectDelayMs` (mero-js has no SSE
backoff). Any `403`, or a `401` whose `x-auth-error` is `token_reuse` /
`token_revoked`, stops the connection.

`presenceSeed(contextId)` is the latest `Ephemeral` data per author for a context the
connection holds, each `ageMs` advanced by the time since it arrived; removals are
dropped, and a reconnect or `unsubscribe` clears it.

## Typed events

```kotlin
data class AppVersionChangedEvent(val contextId: String, val fromVersion: String?, val toVersion: String?)

sealed class GroupMigrationEvent { abstract val groupId: String
    data class MigrationStarted(groupId, fromVersion, toVersion, toStateVersion: Long, localContextsTotal: Long)
    data class MigrationProgress(groupId, migrated: Long, inProgress: Long, unknown: Long, failed: Long, total: Long)
    data class CascadeProgress(groupId, subgroupId, localContextsSwapped: Long, localContextsTotal: Long)  // admins only
    data class MigrationCompleted(groupId, toVersion, completedAt: Long)  // seconds since the epoch
}

sealed class GroupMembershipEvent { abstract val groupId: String; abstract val memberAccount: String; abstract val role: String?
    data class MemberJoined(…); data class MemberAdded(…); data class MemberRemoved(…)
}

fun ContextEvent.asAppVersionChanged(): AppVersionChangedEvent?
fun GroupEvent.asMigrationEvent(): GroupMigrationEvent?
fun GroupEvent.asMembershipEvent(): GroupMembershipEvent?
```

Field names are core's (`crates/primitives/src/events.rs`): `memberAccount` is the
member's account (64 hex), not a signing key; `role` is absent on `MemberRemoved` and
on an inherited Open-subgroup join; `MigrationProgress.total` is the fleet cohort,
`MigrationStarted.localContextsTotal` the emitting node's own count. `Mero` and
`SseClient` also offer `appVersionChanges(contextIds)`, `migrationEvents(groupIds)` and
`membershipEvents(groupIds)` as cold flows.

## `mero.ws` — `WsClient` (experimental)

```kotlin
@ExperimentalMeroApi
class WsClient(baseUrl: String, token: suspend () -> String?, client: OkHttpClient = OkHttpClient(), …, authorize: RequestAuthorizer? = null) {
    val events: SharedFlow<NodeEvent>
    val connects: SharedFlow<Unit>
    val errors: SharedFlow<Throwable>
    val failure: StateFlow<Throwable?>
    val isOpen: Boolean
    fun connect()
    fun subscribe(contextIds: Collection<String> = emptyList(), groupIds: Collection<String> = emptyList())
    fun unsubscribe(contextIds: Collection<String> = emptyList(), groupIds: Collection<String> = emptyList())
    fun isSubscribed(contextId: String): Boolean
    fun close()
    companion object { fun backoffMs(attempt: Int, initial: Long = 1_000, max: Long = 30_000): Long }
}
```

Port of mero-js `WsClient` over OkHttp's WebSocket: `GET /ws` (Bearer header),
messages `{"id":null,"method":"subscribe"|"unsubscribe","params":{contextIds?,groupIds?}}`
(core `server/primitives/src/ws.rs`), every remembered id re-subscribed on each open,
reconnect after `min(1 s · 2ⁿ, 30 s)`, reset by a successful open. A `403` upgrade (or a
`401` naming a dead family) sets `failure` and stops it.

## `SseClient`

`mero.events(...)` builds an `SseClient` for you; use it directly only to manage
the connection yourself.

```kotlin
class SseClient(
    baseUrl: String,
    token: suspend () -> String?,
    client: OkHttpClient = OkHttpClient(),
    json: Json = Json { ignoreUnknownKeys = true },
) {
    fun connection(): SseConnection
    fun events(contextIds: List<String>): Flow<ContextEvent>
    fun groupEvents(groupIds: List<String>): Flow<GroupEvent>
    fun nodeEvents(contextIds: List<String>, groupIds: List<String>): Flow<NodeEvent>
    fun appVersionChanges(contextIds: List<String>): Flow<AppVersionChangedEvent>
    fun migrationEvents(groupIds: List<String>): Flow<GroupMigrationEvent>
    fun membershipEvents(groupIds: List<String>): Flow<GroupMembershipEvent>
}
```

Each flow runs on its own `SseConnection`, closed when the collector is cancelled, and
fails with the terminal refusal if there is one.

<Aside type="note">
  `mero.logout()` does not stop an active stream — tie the collecting coroutine
  to a lifecycle-aware scope (`viewModelScope`, or a Compose `LaunchedEffect`) so
  it's cancelled when the screen goes away.
</Aside>
