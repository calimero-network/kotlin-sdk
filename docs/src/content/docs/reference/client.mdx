---
title: CalimeroClient
description: Every CalimeroClient method, grouped as mero-js groups them.
---

`CalimeroClient(CalimeroClientOptions(baseUrl, nodes, policy, httpClient, retry, onSession))`, or
by cluster name through the node directory:
`CalimeroClient.connect(CalimeroConnectOptions(cluster, policy, directory, zone, …))`.
Every method is `suspend`; paths are relative to the node and sealed.

Methods that change credentials, memberships or invites, deployments and deployers are passkey
step-ups: they take a `passkey` and answer the node's `412 CONFIRM_REQUIRED` with it
(`addPasskey(passkey, approver)`, `removePasskey(id, passkey)`, `createApiKey(options, passkey)`,
`setMember(org, account, role, passkey)`, `removeMember(org, account, passkey)` (also to leave),
`setCapabilities(org, bits, passkey, account?, team?)`, `setTeamMember(org, team, account, passkey, …)`,
`removeTeamMember(org, team, account, passkey)`, `invite(org, role, passkey, teams, ttlSecs, uses)`).
`redeemInvite(token)` needs no approval.

Helpers beside it: `errorFrom`, `fetchAttestedKey`, `claimedRelease`, `pendingApprovalsFrom`,
`releaseConsent`, `withdrawConsent`, `upgradeConsent`, `consentReturn`, `stalledBy`,
`compareVersions`, `publisherBindingMessage`, `OrgCapabilities`, `b64url` / `fromB64url`,
`readDirectory` / `orderNodes` / `DEFAULT_DIRECTORY`, `deployerKey`, `frontendManifest`,
`pageDeployment`, `freshCollateral`.

Where Kotlin differs from mero-js in shape only: `AbortSignal` → cancel the coroutine (and
`events` is a `Flow`); option objects → named parameters; `'unknown' | false` → `Committed`;
`createApp(name, string | {package…})` → `AppSource.Bundle` / `AppSource.Package`; a session
change is reported through `onSession` / `onSessionChange` so it can be stored.
