`mero.admin` (`AdminApi`) is the node's `/admin-api` REST surface — the full set
(~140 methods) across applications, contexts, namespaces, groups, blobs, aliases,
capabilities, metadata, upgrades, accounts/devices, and TEE. Every method is a `suspend fun` over
the shared [`HttpClient`](/get-started/quickstart/); most reads unwrap the node's
`{ data }` envelope for you. Endpoints below are relative to `/admin-api`.

List methods return the node's full result set — the admin API does not paginate,
so there are no limit/offset/cursor parameters. The one exception is
`listMemberDevices` / `listGroupMemberDevices`, which take optional `offset` and
`limit`.

:::note[Pinned to core 0.11.0-rc.83]
rc.83 removed `GET /certificate` (so `getCertificate` is gone), `teeVerifyQuote`
went with its long-dead route, `CreateGroupRequest` lost `groupId` (ids are
derived; naming one is a `400`), and an absent subgroup `visibility` now means
**open**. Refusals answer with typed statuses — see
[Error model](/reference/error-model/).
:::

### Root-guarded owner ops (core 0.11.0-rc.83)

`transferOwnership`, `changeNamespaceAdmin`, `ownerDeleteGroup`,
`setTeeAdmissionPolicy` and the TEE authoring policy are **owner** operations:
they need a proof signed by the owner account's **root** key, not just a device.
Pass it as `rootProof` (hex borsh `SignedOwnerOp`), or call a node that holds the
owner's root and let it sign. With neither, `403`.

The proof names the group's `namespaceId` and `ownerOpCounter` — read both from
`getGroupInfo` first. A stale counter is a **`409`**: re-read and re-sign. An
empty `rootProof` is a `400`; omit the field instead. `ownerDeleteGroup` needs a
group with no contexts; `deleteGroup` stays the admin-level cascading delete.

:::caution[Two TEE admission forms (core 0.11.0-rc.83)]
Build the request with `SetTeeAdmissionPolicyRequest.measurements(…)` or
`.signedRelease(…)`:

- **Measurements** — `allowedMrtd`, `allowedRtmr1`, `allowedRtmr2` and
  `allowedRtmr3` must all be non-empty, even with `acceptMock` (a mock fleet
  names the all-zero measurement). An empty list is a `400`, not a wildcard.

  the named image `allowedProfiles` (and an optional `minReleaseVersion`). Every
  measurement list must then be empty.

admits TEEs as `RelayTee` — able to author members' writes under their warrants)
and `rootProof`. The GET adds `enabled`, `signedRelease` and `mode`.

### `syncGroupContexts` — the anti-"uninitialized context" helper

Joining a group does not initialize its contexts on your node: cross-node sync is
asynchronous, and until a context is joined **and** state-pulled it sits on the
all-ones (`1111…`) uninitialized hash, so every read looks empty.
`syncGroupContexts` does the whole dance for you:

```kotlin
// sync the group, then join + state-pull every context in it
val contexts = mero.admin.syncGroupContexts(groupId)
```

It runs `syncGroup`, lists the group's contexts, then `joinContext` +
`syncContext` for each, tolerating per-context failures (sync is async — call it
again). The sample app's chat calls it in a short retry loop right after
`joinNamespace`, which is what makes an invited space's channels appear.

<Aside type="tip" title="`relink` adds, `scope` replaces (core 0.11.0-rc.41)">
`relinkDevice` is add-only, so it can widen a device's reach but never narrow it.
`rescopeDevice` is the other direction, and a `PUT` for that reason: it replaces
the scope outright.

The body is `{"scope":"all"}` or `{"scope":{"only":["<application id>", …]}}` —
serde's externally-tagged enum, so `DeviceScope.All` is the bare **string**
`"all"`, not an object. Tagged rather than a list whose emptiness means
everything (which is what `relink` uses): here an empty `only` is refused with a
`400`, instead of the narrowest slip becoming the widest possible grant.

Both routes must run on the node **holding the account root** — only its key can
sign the change. The device is not consulted and need not be online.

`labelDevice` names a device so a listing renders as something other than 64 hex
characters. The name replicates: it comes back on `AccountDevice.label` for every
device of the account, and `labelEpoch` orders it against a rename made elsewhere
at the same moment.
</Aside>

<Aside type="caution" title="Three of these answer flat, not enveloped">
`GET /account/devices`, `GET /account/applications` and
`GET /groups/{id}/member-devices` return `{devices:[…]}` / `{applications:[…]}` /
`{members:[…]}` with **no `data` wrapper**, unlike every route around them.
Decoding one as an envelope yields `null` and reads as "empty".
</Aside>


<Aside type="note" title="Pairing statements expire (core 0.11.0-rc.83)">
The pairing `statement` is now 72 bytes (144 hex) and carries a timestamp:
`pair-complete` refuses one older than 300 s. The SDK relays it opaquely.
</Aside>

## Delegated execution (core 0.11.0-rc.83)

A member who cannot run the application — a device holding only a signing key —
asks a node to act for it under a signed **warrant**. These calls take warrants
and proofs as opaque hex; minting them is the account layer's job. On a node
running with `delegated_access`, the routes are public (the warrant is the
credential).

| Method | Endpoint |
| --- | --- |
| `getIntentRelay(contextId): IntentRelayInfo` | `GET /contexts/{contextId}/intents` |
| `createContextIntent(groupId, request): CreateContextIntentResponseData` | `POST /groups/{groupId}/context-intents` |
| `getContextIntentRelay(groupId, author? = null): ContextIntentRelayInfo` | `GET /groups/{groupId}/context-intents[?author=]` |
| `governanceIntent(groupId, request): GovernanceIntentResponseData` | `POST /groups/{groupId}/governance-intents` |
| `getGovernanceIntentRelay(groupId): GovernanceIntentRelayInfo` | `GET /groups/{groupId}/governance-intents` |
| `presenceIntent(contextId, request)` | `POST /contexts/{contextId}/presence-intents` (`204`) |
| `getWarrantNonce(contextId, authorDeviceKey): WarrantNonceState` | `GET /contexts/{contextId}/warrant-nonce/{key}` |
| `getWarrantNonceAsAuthor(contextId, authorProof): WarrantNonceState` | `POST /contexts/{contextId}/warrant-nonce` |

Read `getIntentRelay` **before** signing: a warrant must name exactly its
`executorAccount`, `executorKey`, `releaseBytecodeId` and `releaseVersion`, and a
warrant naming anything else spends a nonce and is refused. `canAuthorOnBehalf:
false` is an answer, not an error — an admin of `groupId` grants
`Capabilities.CAN_AUTHOR_ON_BEHALF` (`openToDelegatedExecution` /
`grantAuthorship`).

:::caution[Warrant-nonce routes are newer than rc.83]
A node without them answers `404`, which the SDK throws as
`WarrantNonceRouteUnavailableException` — fall back to your own counter. Nonces
are `ULong`, parsed from the literal digits, never through a `Double`.
:::

:::caution[`upgradePolicy` is gone]
core#3485 removed the concept — it always held `"LazyOnAccess"` — so neither
`Namespace` nor `GroupInfo` carries it, and neither `CreateNamespaceRequest` nor
`CreateGroupRequest` sends it. A model that still declares it **required** throws
`MissingFieldException` on every read; `ignoreUnknownKeys` does not help, because
the problem is a missing field, not an unknown one.

Timestamps are `Long`, not `Int`: `MetadataRecord.updatedAt` is wall-clock
**milliseconds** and overflows a 32-bit `Int` today.
:::
