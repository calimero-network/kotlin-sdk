Instead of polling, subscribe to a context's real-time events. `mero.events(contextIds)`
opens a Server-Sent-Events stream and emits a `ContextEvent` for each node
emission — new messages, application-version flips, and other context activity —
so a screen can react as changes arrive.

## Subscribe

`events(contextIds)` returns a cold `Flow<ContextEvent>`. Collect it inside a
coroutine you can cancel:

```kotlin
val job = scope.launch {
    mero.events(contextIds = listOf(contextId)).collect { event ->
        when (event.kind) {
            "StateMutation" -> reloadMessages()          // the context state moved
            "SyncStatus" -> updateSyncIndicator(event)   // syncing / waitingForPeers / …
            else -> println("event on ${event.contextId}: ${event.kind}")
        }
    }
}
```

Each event is:

```kotlin
data class ContextEvent(
    val contextId: String,
    val kind: String,          // "StateMutation" | "SyncStatus" | …
    val payload: JsonElement,  // raw event JSON
)
```

:::caution[The kind is `StateMutation`, not `ExecutionEvent`]
Earlier versions of this page said `ExecutionEvent`. No node sends that, so the
branch never fired — captured verbatim from a live `merod 0.11.0-rc.32`:

```json
{"result":{"contextId":"7359dc15…","type":"StateMutation",
  "data":{"newRoot":"b116ecf2…",
          "events":[{"kind":"MessageSent","data":[123,34,…],"handler":null}]}}}
{"result":{"contextId":"7359dc15…","type":"SyncStatus",
  "data":{"syncState":{"state":"waitingForPeers"},"failureCount":0}}}
```

If you only need "something changed", don't branch at all — the chat sample just
reloads on every event, which is why it was unaffected.
:::

For a contract emission (`kind == "StateMutation"`) the encoded contract events
are nested under `payload`'s `data.events[].data`; each carries its own `kind`
(`MessageSent` above) and a byte array.

## The token needs `context:subscribe`

:::danger[core 0.11.0-rc.41 put a permission on the event transports]
Before rc.41 (core#3942), `/sse`, `/sse/subscription` and `/sse/session/{id}`
required **no permission at all** — any valid token could open a stream. They now
map to `context:subscribe`, so a token minted with a narrow permission list that
does not name it is refused with a `403` and no events ever arrive.

`context:subscribe` is **not** implied by `context`: core's `ContextPermission::All`
arm matches only another `All`. `admin` does cover it, which is what
`mero.authenticate()` requests — so credential login is unaffected. A scoped SSO
login must ask for it explicitly:

```kotlin
AuthLoginOptions(
    callbackUrl = "myapp://auth-callback",
    mode = "login",
    permissions = listOf("context:subscribe", "context:execute"),
)
```
:::

## Reconnection

The stream reconnects automatically ~3 seconds after a drop and re-subscribes to
your context ids (the node persists the session's subscriptions). You don't need
to rebuild the flow on a transient network blip — the collector keeps delivering
events across reconnects.

A **`403` is the exception**, and it ends the flow rather than restarting it. Two
things produce one: a token that never carried `context:subscribe`, and a refresh
family that was revoked (core answers that with `x-auth-error` and an empty body).
Neither is fixed by waiting, so retrying every three seconds is not resilience —
it is a silent outage, a live-looking subscription delivering nothing while no
exception ever reaches the collector. Instead:

- a revoked family throws `AuthRevokedException` — route the user back to login;
- any other `403` throws `HttpException(status = 403)` — the token is missing
  `context:subscribe`.

```kotlin
scope.launch {
    try {
        mero.events(listOf(contextId)).collect { reload() }
    } catch (e: AuthRevokedException) {
        forceReLogin()
    } catch (e: HttpException) {
        if (e.status == 403) reportMissingSubscribeGrant()
    }
}
```

## Closing the stream

The stream lives for as long as its collecting coroutine — **cancel that job** (or
the enclosing scope) to close the SSE connection:

```kotlin
job.cancel()   // closes the connection
```

<Aside type="caution">
  `mero.logout()` does **not** stop an in-flight event stream. Tie the collector
  to a lifecycle-aware scope (`viewModelScope`, or a Compose `LaunchedEffect`) so
  it's cancelled when the screen goes away.
</Aside>

## In Compose

`LaunchedEffect(contextId)` ties collection to a composable's lifetime — it starts
when the composable enters composition and is cancelled when `contextId` changes
or it leaves:

```kotlin
@Composable
fun MessagesScreen(mero: Mero, contextId: String) {
    var messages by remember { mutableStateOf(emptyList<Message>()) }

    LaunchedEffect(contextId) {
        mero.events(contextIds = listOf(contextId)).collect {
            messages = loadMessages()
        }
    }

    MessageList(messages)
}
```
