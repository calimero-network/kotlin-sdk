---
title: User approvals
description: Ask the account holder to approve a release, an upgrade, outbound hosts, a new organization or an invitation on the node's consent page, opened in a Custom Tab.
---

Approvals happen **only on the node's consent page**, never in the app: a session opened on an
app is refused (`403`) if it tries `approveRelease` itself.

```kotlin
// What waits for a decision: unapproved node releases, newer package releases, a stalled deadline.
val pending = client.pendingApprovals(org)

// Ask: POST /consent/requests, then open the page in a Custom Tab.
val started = ConsentLauncher.request(
    activity,
    client,
    ConsentRequest.Release(ConsentScope(org), pending.releases.first().version, returnTo = "myapp://consent"),
)
```

`started.code` is the request's confirmation code (`ABC-123`); the consent page shows the same
one, so show it in the app before the page opens.

The page sends the person back to `returnTo?request_id=…&result=approved|declined`. That is a
hint (anyone can type a URL): confirm it with the node.

```kotlin
// In the activity that receives the App Link (null when the intent is not a consent return):
val result = ConsentLauncher.resume(client, intent)       // or client.resumeConsent(url)
// or poll, when the link does not come back:
val polled = client.waitForConsent(started.requestId, timeout = 10.minutes)
```

The four steps are the same in mero-js and swift-sdk (`request / begin / resume / wait`):

| Step | mero-core | mero-compose |
|---|---|---|
| request | `client.requestConsent(request)`: `{ requestId, url, code, expiresAt }` | |
| begin | `client.openConsentPage(request, OpenConsentOptions(navigate, confirm))` (checks `code`) | `ConsentLauncher.request(context, client, request, confirm)` (a Custom Tab) |
| resume | `client.resumeConsent(href)` | `ConsentLauncher.resume(client, uri or intent)`, `MeroAppSession.handle(url)` |
| wait | `client.waitForConsent(requestId, timeout)`, `client.consentResult(requestId)` | |

## Organizations and invitations

A package-bound session may not create an organization or mint or accept an invitation itself;
it asks on the consent page like any other approval:

```kotlin
ConsentRequest.CreateOrg(name = "Acme", returnTo = returnTo)
ConsentRequest.CreateInvite(org, OrgRole.MEMBER, returnTo, teams = listOf(team), ttlSecs = 86_400, uses = 1)
ConsentRequest.AcceptInvite(token, returnTo)
```

`returnTo` must be the package's own frontend origin or one its signed manifest names, so on
Android it is a verified App Link on such an `https` origin (an intent filter with
`android:autoVerify="true"` and the origin's `assetlinks.json`).

Once approved, `ConsentResult.outcome` says what the approval did, typed by kind:

```kotlin
when (val outcome = result.outcome) {
    is ConsentOutcome.OrgCreated -> openOrg(outcome.orgId)
    is ConsentOutcome.InviteCreated -> share(inviteLink(outcome.token)) // a bearer secret
    is ConsentOutcome.InviteAccepted -> openOrg(outcome.org)
    ConsentOutcome.Release, ConsentOutcome.Upgrade, ConsentOutcome.Outbound -> refresh()
    is ConsentOutcome.Other -> Unit // a kind this SDK version does not know
    null -> Unit // pending or declined (result.isDeclined)
}
```

An invitation's token is a secret: `ConsentRequest.AcceptInvite` and `ConsentOutcome.InviteCreated`
leave it out of `toString`, so a logged request or result does not carry it. Do not log
`outcome.token` yourself.

`MeroAppSession.requestConsent(context, request)` and `MeroAppSession.handle(url)` do both, and
put the confirmed result in `session.consentResult`.

`409 CONSENT_STALE` means what the page showed changed: ask again. `409 RELEASE_DEADLINE`
(`ReleaseDeadlineError`) means new work is stopped until the scope approves `release`.
