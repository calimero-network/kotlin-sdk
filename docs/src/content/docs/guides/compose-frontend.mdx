`mero-compose` is an optional Jetpack Compose layer that ships alongside the core
SDK — a `MeroClient` view-model exposing a `StateFlow<MeroAuthState>`, a
`MeroProvider`/`useMero` pair for passing it down the tree, and ready-made
`LoginSheet` / `ConnectButton` composables. It's the port of mero-react: `MeroClient`
is its `MeroProvider` (the `useMero()` value), the [state holders](/guides/compose-state/)
are its hooks, and the [invitation flow](/guides/compose-invitations/) is its
`invitations` module. On a phone, sign-in is "Continue with Calimero" (the **Cloud**
tab); a node you run can be signed in to through its own login page (the **Node**
tab). See [Authentication](/get-started/authentication/#sign-in-with-calimero-mobile)
for what happens underneath.

Add the optional dependency (see [install](/get-started/quickstart/#install)):

```kotlin
implementation("com.calimero.mero:mero-compose:0.1.0")
```

## Wire it up

Build a `MeroClient`, provide it with `MeroProvider`, then read it anywhere below
with `useMero()`:

```kotlin
import com.calimero.mero.compose.*

@Composable
fun App(context: Context) {
    // Production factory: device keys + session in EncryptedSharedPreferences
    val client = remember { MeroClient.create(context) }
    LaunchedEffect(Unit) { client.restore() }          // reconnect a saved session

    MeroProvider(client) {
        val c = useMero()               // the client, anywhere in the tree
        val state by c.state.collectAsStateWithLifecycle()
        if (state.isAuthenticated) HomeScreen() else LoginSheet(callbackUrl = "myapp://calimero-enrol")
    }
}

// The Activity that owns the callback intent filter forwards every redirect — the
// wallet's, and a node login page's SSO callback:
override fun onNewIntent(intent: Intent) {
    super.onNewIntent(intent)
    intent.data?.toString()?.let { lifecycleScope.launch { client.handleDeepLink(it) } }
}
```

## `MeroClient`

A plain (non-composable) class: mero-react's `MeroProvider` state and actions.
`MeroAuthState` carries `isAuthenticated`, `isLoading`, `account`, `device`,
`relayUrl`, `sessionReady`, `relayNote`, `cancelled`, `error`, `nodeUrl`,
`username`, `isOnline`, `isOfflineSession`, `applicationId`, `contextId`,
`contextIdentity`, `errorReason`, `errorStatus` and `loginFailure`, plus
`signedInWithoutRelay`, `isNodeSession`, `isDevNodeSession` and `isDelegated`.

`errorReason` says what kind of failure `error` describes, so an app branches on it
instead of matching words: `INVALID_INPUT`, `INVALID_CREDENTIALS` (401/403/400),
`RATE_LIMITED` (429, too many failed attempts), `NOT_FOUND` (404, no login at that
URL), `UNREACHABLE`, `NODE_ERROR` (5xx), `PERMISSIONS_REFUSED` or `UNKNOWN`. `login`
and `connectToNode` set it; it is null for an error it does not classify.
`errorStatus` is the HTTP status, when there was one.

A failed `login` also sets `loginFailure`, a typed `LoginFailureReason`:
`InvalidCredentials`, `RateLimited(retryAfterSeconds)` (the node's lockout, with its
`Retry-After`), `Unreachable`, `NotFound`, `ServerError(status)` or `Other`. A lockout
reads "Too many failed attempts. Try again in N seconds." The built-in messages name
no vendor.

```kotlin
class MeroClient(
    val account: CloudAccount,
    tokenStore: TokenStore = MemoryTokenStore(),
    launchWallet: (Context, String) -> Unit = WalletLauncher::launch,
    val config: MeroAppConfig = MeroAppConfig(),          // mode, packageName, allowedNodeUrls, httpClient, …
    val storage: MeroAppStorage = MeroAppStorage(),       // node URL, application, context
    launchLogin: (Context, String) -> Unit = …,           // a node's login page, in a Custom Tab
    val pendingAuth: PendingAuthStates = PendingAuthStates.shared,
    …
) {
    val state: StateFlow<MeroAuthState>
    val session: StateFlow<MeroSession>   // what the state holders read
    val admin: AdminSurface?              // node admin, or the account admin
    val can: MeroCapabilities             // createNamespace / createContext / invite / upgrade
    val isDelegated: Boolean
    val relay: RelayClient?
    val mero: Mero?

    fun signInWithCloud(context: Context, callbackUrl: String)
    fun connectToNode(context: Context, nodeUrl: String, callbackUrl: String)
    suspend fun handleDeepLink(url: String): Boolean      // enrolment or SSO callback
    suspend fun restore(): Boolean                        // Cloud session, else the stored node session
    suspend fun restoreNodeSession(): Boolean             // the stored node, if it accepts the stored token
    suspend fun resumeNodeSession(): NodeSessionRestore   // the same, keeping the session when the node is unreachable
    suspend fun connectWithAccount(session: DelegatedSession)
    fun selectContext(contextId: String?, contextIdentity: String? = null)
    suspend fun logout()                                  // clears tokens, session and storage

    suspend fun login(                                    // development only
        nodeUrl: String, username: String, password: String,
        permissions: List<String>? = null,                // a scoped client key instead of the admin token
    ): Boolean

    companion object {
        fun create(context: Context, cloudBaseUrl: String = …, walletUrl: String = …, config: MeroAppConfig = …): MeroClient
    }
}
```

### App modes and what a session may do

`MeroAppConfig.mode` is mero-react's `AppMode` — `MULTI_CONTEXT` (the default),
`ADMIN`, and the deprecated `SINGLE_CONTEXT` — and decides the grants a node login
asks for (`permissionsFor(mode)`; `MULTI_CONTEXT` includes `context:subscribe`, which
every event stream needs, and `context:delete`). `can` answers *what is allowed*: a
node session can do everything (`MeroCapabilities.NODE`); an account can create
contexts and invite, founds a namespace only when the app names its `packageName`,
and never upgrades.

`admin` is the one admin API to write against: a node's (`createNodeAdmin`, which
installs the app's package before founding a namespace when needed) or the account
admin (`createAccountAdmin`, reads from the relay, writes as delegated ops). For an
account, `applicationId` is derived — from the registry by `packageName`, else from the
account's contexts when they name exactly one application.

### Node sessions and SSO

`connectToNode` records the node as the trust anchor and opens its login page
(`buildAuthLoginUrl` with this app's mode, grants and package, and a single-use
`auth_state`). The callback is accepted only when:

1. it answers a login started here (`PendingAuthStates`);
2. its `node_url` shares the started node's origin, or — with no started node — is in
   `MeroAppConfig.allowedNodeUrls` (`resolveTrustedNodeUrl`, mero-react
   `auth/node-trust.ts`). An untrusted one stores nothing and restores any existing
   session, so a tampered link cannot log anyone out;
3. its tokens are adopted only when nothing is stored, the node changed, they are
   newer, or they fill a missing refresh token (`resolveTokenAdoption`, mero-react
   `auth/token-adoption.ts`) — never over a bundle the SDK already rotated, which the
   node would read as refresh-token reuse and revoke the whole family.

The session is then checked with `/auth/validate` (no permission needed), and the
application, context and identity the callback named are kept in `MeroAppStorage`
(SharedPreferences, mero-react's keys). `isOnline` follows the node's event stream: a
connect is online, a failure offline; a revoked family or a `403` naming an auth error
(a token minted without `context:subscribe`) logs out; a `401` is first recovered
through `/auth/validate`. A development `login` is monitored the same way.

For an app that works offline, restore the node with `resumeNodeSession()`. It answers
`RESTORED`, `REJECTED`, `NO_SESSION`, or `OFFLINE` when the node gave no verdict (no
network, a timeout, a `5xx`: `ValidationResult.isUnreachable`). On `OFFLINE` the client is
signed in on the held tokens with `isOnline == false` and `isOfflineSession == true`; both
clear when the node's event stream connects, and a node that then rejects the tokens logs
out. Ask for sign-in only on `REJECTED` or `NO_SESSION`.

`login` is for development against your own `merod` (from the emulator,
`http://10.0.2.2:2428`). Do not ship it.

`handleEnrolmentCallback` verifies the certificate against this device's own keys
and the `state` it sent before storing anything. A declined approval sets
`cancelled`, not `error`.

## Drop-in composables

All default their `client` to `useMero()` and their colours to the ambient `MeroTheme`:

| Composable | Purpose |
| --- | --- |
| `MeroProvider(client) { … }` | provides the `MeroClient` via a `CompositionLocal` |
| `useMero()` | reads the provided client (throws if no provider above) |
| `LoginView(callbackUrl, mode, nodeSignIn, branding, nodeCallbackUrl, onConnectNode)` | the sign-in screen: **Cloud** ("Continue with Calimero Cloud") and, behind a "Manually enter node URL" link, a **node** (local nodes found on `10.0.2.2` on an emulator, `localhost` on a device, plus a manual URL) |
| `LoginSheet(callbackUrl, tabs, initialTab, nodeCallbackUrl, onConnectNode, colors)` | the older form of `LoginView`: `tabs` map to a `LoginMode` |
| `ConnectButton(callbackUrl, onConnect, labels, logoOnly, tabs)` | "Connect" (opens the sheet), "Reconnecting...", or "Connected" with the account / node and "Log out" |
| `CalimeroLogo(size, color)` | the emblem (`CalimeroLogoVector`) |
| `MigrationPendingBanner(contextId, onMigrated)` | "re-sign your entries" with a one-tap convert |
| `MigrationAdminPanel(namespaceId, pollIntervalMs)` | a namespace's migration rollup and members |
| `InvitationDialog`, `InvitationGate`, `JoinSyncBanner` | see [Invitations](/guides/compose-invitations/) |

```kotlin
LoginView(
    callbackUrl = "myapp://calimero-enrol",
    mode = LoginMode.CLOUD_AND_NODE,             // or CLOUD_ONLY / NODE_ONLY
    nodeSignIn = NodeSignInMethod.LOGIN_PAGE,    // PASSWORD: admin username + password (a dev merod)
    branding = LoginBranding(cloudTitle = "Welcome to My App"),
    onAuthenticated = { /* navigate home */ },
)

ConnectButton(callbackUrl = "myapp://calimero-enrol")
```

- `LoginMode`: `CLOUD_AND_NODE` (Cloud, with a small "Manually enter node URL" link that
  toggles to "Use Calimero Cloud instead"), `CLOUD_ONLY` or `NODE_ONLY`. `LoginMode.from(tabs)`
  maps the older `LoginModalTab` lists.
- `NodeSignInMethod`: `LOGIN_PAGE` (the node's own login page; the default) or `PASSWORD`
  (`MeroClient.login`).
- `LoginBranding`: `cloudTitle`, `cloudSubtitle`, `nodeTitle`, `nodeSubtitle`, `cloudButton`, `logo`,
  and every other string on the screen, so an app can rebrand it completely: `cloudHint`,
  `cloudCancelled`, `customWalletNote`, `manualNodeLink`, `useCloudLink`, `searchingNodes`,
  `localNodeTag`, `manualNodeOption`, `nodeUrlLabel` / `nodeUrlPlaceholder`, `usernameLabel` /
  `usernamePlaceholder`, `passwordLabel` / `passwordPlaceholder`, `nodeButton` and `rescanNodes`.
  The defaults are the Calimero copy. `LoginSheet`, `AccountSignInPanel` and `ConnectButton` take
  the same `branding`.

Test tags: `loginTitle`, `loginError`, `cloudSignInButton`, `loginButton` (the Cloud panel),
`cloudLoginCancelled`, `manualNode` / `useCloud`, `nodeDiscovering`, `nodeOption-…`,
`nodeUrlInput`, `nodeUserInput`, `nodePasswordInput`, `rescanButton` and `nodeConnectButton`.
They replace the sheet's earlier `cloudLoginTitle` / `cloudLoginButton` / `loginTabNode` tags.

### Theme

`MeroTheme` has mero-react's tokens (`primary`, `primaryHover`, `primaryText`,
`background`, `backgroundSecondary`, `backgroundTertiary`, `border`, `text`,
`textSecondary`, `error`, `overlay`, `radius`) plus, as in the Swift SDK, `surface`,
`textTertiary`, `success`, `warning`, `cardRadius`, `controlHeight`, `titleFontFamily` and
`showsGlow` (each derived from the others when not given).

Presets: `MeroTheme.calimeroLight` (warm off-white, white cards, lime fills; the default
`LocalMeroTheme`) and `MeroTheme.calimero` (mero-react's dark palette, also
`defaultMeroTheme`). Provide one with `ProvideMeroTheme(theme) { … }` and restyle with
`copy(...)`:

```kotlin
ProvideMeroTheme(MeroTheme.calimeroLight.copy(primary = Color(0xFF5B5BD6), primaryText = Color.White, showsGlow = false)) {
    LoginView(callbackUrl = "myapp://calimero-enrol")
}
```
